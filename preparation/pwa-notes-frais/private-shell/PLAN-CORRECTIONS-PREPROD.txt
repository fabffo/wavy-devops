M1 — Intégrité cinq bases/documents
Au point de quiescence du backup, capturer baseline cohérente (hook futur autorisé) :
version serveur, schémas/extensions, tables/colonnes, contraintes, index, séquences,
historiques Flyway et comptages exacts par table ; aucun SELECT métier brut dans logs.
Sur copies : comparer 100 % inventaire/comptages, contraintes validées, séquences
et ensemble références ndf tenant/société/note ; resolver autorisé de chemin -> hash,
taille/MIME selon contrat, chaque référence doit désigner un fichier attendu.
Contrats ET Notes : tous fichiers hash identiques ; 0 référence manquante, 0 divergence
inexpliquée, orphelins recensés/acceptés sans suppression. Contraintes préexistantes
non validées : exception revue explicitement, jamais succès automatique.
Séquences : comparer last_value/is_called au snapshot cohérent, avec précautions
sur allocations non transactionnelles ; pas d'égalité naïve à max(id).
Requêtes génériques pour une copie (via pg exec DU helper uniquement) :
 SELECT version();
 SELECT extname,extversion FROM pg_extension ORDER BY extname;
 SELECT n.nspname,c.relname,c.relkind FROM pg_class c JOIN pg_namespace n ON n.oid=c.relnamespace WHERE n.nspname NOT IN ('pg_catalog','information_schema') AND n.nspname NOT LIKE 'pg_toast%' ORDER BY 1,2;
 SELECT conrelid::regclass,conname,contype,convalidated FROM pg_constraint WHERE connamespace NOT IN (SELECT oid FROM pg_namespace WHERE nspname IN ('pg_catalog','information_schema')) ORDER BY 1,2;
Pour comptes exacts, quotes identifiants SQL avec format('%I',...), transaction
repeatable-read/read-only ; mapper le schéma réel avant génération des requêtes
Notes/Contrats. Ce mapping est encore à revoir : aucune requête métier improvisée.
