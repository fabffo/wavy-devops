1. Architecture corrigée
ERP Shell/Nginx Docker conservés, entrée unique 127.0.0.1:24443. Aucun DNS,
Nginx natif ou port 80/443. L'écoute supplémentaire 127.0.0.1:8087 existe seulement
DANS le conteneur pour la redirection /pwa après auth_request ; aucun mapping
Compose. Le port est inaccessible sur les interfaces réseau du conteneur.
La PWA reste résolue dynamiquement sur wavy-preprod ; son absence ne bloque
pas le démarrage Nginx ou l'ERP. /api/ et les cinq modules sont conservés.
Les chemins API matriciels, les pourcentages résiduels après normalisation et
les doubles encodages sont refusés avant proxy ; les query strings ordinaires
ne sont pas concernées. Ce rejet concerne toutes les routes /api/ : vérifier
les usages ERP de paramètres matriciels/chemins contenant un pourcentage avant
approbation ; aucune modification de données ni des contrôles backend.

session-gate.py remplace définitivement le marqueur open (désormais ignoré).
Communication auth_request par socket Unix, aucun port TCP, endpoint interne
Nginx non appelable par le client. Le service Python est hors conteneur PWA,
sans Nginx hôte ; il ne peut qu'autoriser ou refuser une session.
Par défaut fermé, ouverture seulement au démarrage avec --authorize-test et
un fichier cookie 0600 dans un parent 0700 appartenant à l'opérateur. Fichier
régulier sans symlink, lecture bornée ; cookie unique WAVY_SESSION obligatoire.
La valeur de session n'est conservée qu'en hash SHA-256 en mémoire du service.
Durée 1..900 secondes : contrôles monotone et UTC à chaque requête, timer de
fermeture supplémentaire, recul d'horloge ferme, redémarrage fermé sans reprise
automatique des arguments d'ouverture. SIGUSR1 ferme définitivement le grant
courant. Crash/arrêt/socket absent => PWA 404 et écritures Notes 403 ; délais
proxy gate 1 seconde. Aucun reload Nginx requis pour fermer.
Tout autre cookie/session est refusé. Le hash ne remplace jamais les contrôles
de session backend ; session révoquée/tenant/société/utilisateur restent vérifiés
par Gateway/API. Changement de société avec le même cookie reste possible.
Si le login renouvelle le cookie, il faut clore puis autoriser explicitement la
nouvelle session dans une nouvelle fenêtre ; aucun renouvellement automatique.

Le socket 0666 ne propose qu'un check lecture seule ; son répertoire 0755 est
inscriptible seulement par l'opérateur, monté RO dans Shell. Un utilisateur local
ou conteneur ayant déjà accès à une session valide reste dans le modèle de
confiance de cette session ; ce dispositif ne protège pas d'un administrateur
Docker/root. Les logs du gate n'impriment ni cookie ni contenu documentaire.
Le contrôle d'ouverture opérateur est manuel : il n'atteste PAS la disponibilité
des preuves de release. L'adaptateur d'orchestration privée manque encore.

Les écritures de toutes méthodes hors GET/HEAD sous /api/notes-frais sont
soumises à la même session temporaire, y compris justificatifs et transformations.
Cela bloque aussi les écritures ERP Notes des autres utilisateurs pendant le
test/fermeture ; à accepter dans la fenêtre de maintenance. Les lectures ERP
restent sous l'authentification existante. /api/pwa reste fermé sans autorisation.
pwa-integration.json conserve enabled=false, accès test direct /pwa/ seulement.
